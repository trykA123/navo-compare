## Goal

The user installs Navo Compare on Windows without Navo, starts it, picks two sides on the start screen or on the command line, and works in tabs. Wave 1 builds the parts that need no compare screen: the command line, the profile, the sessions store, the bench data and an empty window on the pinned `navo` crates.

Appetite: four days of agent work for the whole stage; wave 1 is one day. A wave that runs over stops and needs a new decision.

## Decisions

Final. Workers never reopen them. All `D…` and `NC…` ids are in `plans/2026-11-11-standalone.md`; this plan adds `NS…` ids, local to it.

- **NS1 — Crates.** Plain logic lives in library crates with no GPUI, so it builds and tests in seconds on any host.
  - `navo-compare-cli` (lib): argument parser, side specs, exit codes. Depends on `std` only.
  - `navo-compare-profile` (lib): profile folders, format versions, the sessions store. Depends on `serde` and `toml`.
  - `xtask` (bin): `bench-data`, later `lock-drift`. Depends on `std` only.
  - `navo-compare-app` (bin): the GPUI shell. The only crate that depends on `navo` crates.
  - Alternative lost: one crate with modules. A GPUI build takes minutes, and a backend worker would pay it for every test run.
- **NS2 — One positional argument opens the start screen with the left side filled.** NC10 names only the two-side form. The Explorer menu's first pick uses the same path.
- **NS3 — A side with `@` in it.** The whole text is a path when it exists on disk. Otherwise the `@` signs are tried from the right: the first one whose text before it is not empty and exists makes a `repo@rev`, so `repo@main@{1}` works. Otherwise it is a path, and the start screen reports "not found". The parser gets the "exists" test as a function, so it stays pure.
- **NS4 — Profile folders follow `navo-store/src/dirs/mod.rs` at the pin.** Windows: settings in `%APPDATA%\NavoCompare`, data in `%LOCALAPPDATA%\NavoCompare`. Other hosts: `$XDG_CONFIG_HOME` or `~/.config`, and `$XDG_DATA_HOME` or `~/.local/share`, each with `navo-compare`. `--profile <dir>` puts both in `<dir>`. The data folder holds `profile.toml`, `sessions/`, `cache/`, `journal/`, `logs/`, `crashes/`.
- **NS5 — Session files.** One TOML file per session, `sessions/<id>.toml`. An id is 1–40 characters of `0-9`, `a-f` and `-`; any other file name in the folder is ignored, so a file name can never become a path. A "Two texts" session is never stored (NC26).
- **NS6 — Dependencies.** Each new dependency is added with `cargo add` at the newest stable release, the lockfile is committed, and builds run with `--locked`. `cargo deny` arrives with the gate atom G1.
- **NS8 — A newer `profile.toml` stops the app.** It is the one exception to "load what is known" in NC27: the marker says the whole folder has a newer layout, so the app shows the two versions and exits with code 2, changing nothing. A version under 1 is a broken file.
- **NS9 — A stored session keeps resolved sides.** A side is saved as its kind, an absolute path and, for Git, the rev. The text the user typed is not parsed again on load, so a file created later cannot change what a session means. Rules are stored with the engine's own values (`navo-compare/src/text/normalise.rs` at the pin: whitespace keep, all, changes, trailing; BOM).
- **NS10 — Brand in one module (NC41).** `navo-compare-profile::brand` holds `NAME = "Sidewise"`, `FOLDER = "Sidewise"` and `SLUG = "sidewise"` (NC44). No other file spells the product name.
- **NS7 — Who builds what (owner, 2026-11-11).** UI atoms: Claude `ui-builder`, Sonnet 5.5 medium. Backend atoms: DeepSeek through the Qwen Token Plan on the `dsh` harness (`qwen-plan:deepseek-v4.1-flash-1017`), outside its peak hours. Every backend diff gets a Sonnet review and the orchestrator's read before merge.

## Risks and rollback

- **RS1 — `navo-ui` does not build as a Git dependency.** Navo patches `gpui-pre-windows` from a vendored folder, and a patch does not pass through a dependency (NC32). U0 is a spike that proves the build before any screen is planned; if it fails, U0 reports the error and waves 2–4 are replanned.
- **RS2 — A parser accepts something dangerous.** The NC21 rev rule and the NC23 limits (256 arguments, 64 KiB) are in B1's contract and tests.
- **RS3 — The sessions store loses a session on a crash.** B4 writes to a temp file, syncs it and renames it; a test leaves a half-written temp file behind and the old session still loads.
- **RS4 — The bench generator fills the disk.** B5 refuses a folder that is not empty and prints the size before set L; set L is never part of a test.
- **Rollback.** Every atom is additive: revert its squash commit. Nothing ships until the release atom.

### B1 — the command-line parser

- **Read:** `plans/2026-11-11-standalone.md`, the NC10, NC21 and NC23 entries only; `crates/navo-compare-app/src/main.rs` (17 lines); `Cargo.toml` (16 lines).
- **Change:** in `crates/navo-compare-cli`: new `src/args.rs` and `src/args_tests.rs`, and the `mod` lines in `src/lib.rs`. Do not change `main.rs`.

  ```rust
  pub struct Invocation {
      pub action: Action,
      pub wait: bool,
      pub new_window: bool,
      pub read_only: bool,
      pub profile: Option<PathBuf>,
      pub left_title: Option<String>,
      pub right_title: Option<String>,
  }
  pub enum Action { Start { left: Option<SideSpec> }, Compare { left: SideSpec, right: SideSpec }, Version, Help }
  pub enum SideSpec { Path(PathBuf), GitRev { repo: PathBuf, rev: String } }
  pub enum ArgError {
      UnknownFlag(String), MissingValue(&'static str), NotUnicode, BadRev(String),
      ThreeWay, TooManyArgs(usize), TooLong(usize),
  }
  pub enum Exit { Ok = 0, Discarded = 1, Error = 2 }   // a three-way merge returns Ok only when saved with no conflict left (NC38)
  pub const MAX_ARGS: usize = 256;
  pub const MAX_BYTES: usize = 64 * 1024;
  pub fn parse(args: &[OsString], cwd: &Path, exists: &dyn Fn(&Path) -> bool) -> Result<Invocation, ArgError>;
  ```

  - `args` excludes the program name. Checks run in this order, and the first failure is the result: more than `MAX_ARGS` items gives `TooManyArgs`; more than `MAX_BYTES` bytes in all items together gives `TooLong`; an item that is not valid Unicode gives `NotUnicode`. Only then are flags read.
  - Flags: `--wait`, `--new-window`, `--read-only`, `--version`, `--help`, and with a value `--profile`, `--left-title`, `--right-title`. A value is given as `--flag value` or `--flag=value`. `--` ends the flags. Any other item that starts with `-` before `--` is `UnknownFlag`, with two exceptions: a lone `-` is a positional, and `-o` gives `ThreeWay`. `--version` or `--help` before `--` wins over every flag error and every positional; `--version` wins over `--help`.
  - A flag without a value that is written with `=` (`--wait=1`) is `UnknownFlag` with the whole item. A value flag takes the next item whatever it starts with; no next item, or an empty value after `=`, is `MissingValue`. A repeated flag keeps its last value.
  - Positionals: none gives `Start { left: None }`; one gives `Start { left: Some }` (NS2); two give `Compare`; three or four give `ThreeWay`; more give `TooManyArgs`.
  - A side (NS3): join a relative path to `cwd` without touching the disk. If `exists(whole)` it is `Path`. Else try each `@` from the right: the first one whose text before it is not empty and for which `exists` is true gives `GitRev`, with everything after that `@` as the rev. Else it is `Path`.
  - A rev (NC21) is refused with `BadRev` when it is empty, starts with `-`, holds a control character or is longer than 256 bytes.
  - `ArgError` implements `Display` with one plain sentence each; `ThreeWay` says that three-way merge arrives in a later release.
- **Check:** `cargo test -p navo-compare-cli --locked > ../B1.log 2>&1; echo $?` prints 0. Tests cover every bullet above, including `a@b` when the file `a@b` exists, a rev `-x`, `@main`, `repo@main@{1}` when only `repo` exists, `--profile=dir`, `--profile -x`, `--profile=`, `--wait=1`, a flag given twice, `-o out`, `--` followed by `-file`, `--version` together with an unknown flag, 257 arguments, and 65 KiB of arguments. Then `cargo clippy -p navo-compare-cli --all-targets --locked -- -D warnings` exits 0.
- **Stop if:** NC10 and this contract disagree.

### B4 — the sessions store

- **Read:** `crates/navo-compare-profile/src/paths.rs` after B3; NC8, NC26, NC27 and this plan's NS5.
- **Change:** `src/session.rs`, `src/session_store.rs`, `src/session_tests.rs` in `navo-compare-profile`; one `pub mod` line each in `lib.rs`.

  ```rust
  pub const SESSION_VERSION: u32 = 1;
  pub const RECENT_KEPT: usize = 20;
  pub struct Session {
      pub version: u32, pub id: String, pub name: Option<String>, pub kind: SessionKind,
      pub left: SideRef, pub right: SideRef,
      pub rules: Rules, pub filter: String,  // "all" | "differences" | "orphans" | "same"
      pub opened: i64,                       // Unix seconds
      pub view: Vec<String>,                 // the view stack of NC8, opaque here; `#[serde(default)]`
  }
  pub enum SessionKind { Pair, Texts }
  pub struct SideRef { pub kind: SideKind, pub path: PathBuf, pub rev: Option<String> }   // path is absolute (NS9)
  pub enum SideKind { Path, Git }
  pub struct Rules {
      pub whitespace: String,   // "keep" | "all" | "changes" | "trailing"
      pub ignore_bom: bool, pub ignore_line_endings: bool, pub ignore_case: bool, pub respect_gitignore: bool,
  }
  pub enum StoreError { Io { path: PathBuf, error: std::io::Error }, BadId(String), BadSide, NotStorable, Newer { id: String, found: u32 }, Broken { id: String } }
  pub struct SessionStore { /* private */ }
  impl SessionStore {
      pub fn open(dir: PathBuf) -> SessionStore;
      pub fn new_id(&self, now_ms: u64) -> String;
      pub fn save(&self, session: &Session) -> Result<(), StoreError>;
      pub fn load(&self, id: &str) -> Result<Session, StoreError>;
      pub fn list(&self) -> Result<Vec<Session>, StoreError>;   // newest `opened` first; broken and newer files are skipped
      pub fn delete(&self, id: &str) -> Result<(), StoreError>;
      pub fn prune_recent(&self) -> Result<usize, StoreError>;  // deletes unnamed sessions beyond RECENT_KEPT; returns the count
  }
  ```

  - An id is valid when it matches NS5; every method that takes an id returns `BadId` otherwise and touches no file. `new_id` is the time in hex, a `-`, and a counter that makes it unique in the folder.
  - Reading a file has two steps: first only the `version` field (a struct with that one field); a higher version is `Newer` before anything else is parsed. Then the whole `Session`; a file that does not parse, has no `version`, or holds an `id` other than its file name is `Broken`. Unknown fields in a same-version file are ignored.
  - `save` refuses with `BadSide` a side whose path is not absolute, a `Git` side with no rev, and a `Path` side with a rev. A `whitespace` or `filter` value outside its list makes a file `Broken` on read and is refused with `BadSide` on save.
  - `save` refuses `SessionKind::Texts` with `NotStorable`. It reads the file on disk first: `Newer` or `Broken` there refuses the save with that error and leaves the file byte for byte. It creates the folder when missing, writes `<id>.toml.tmp`, syncs it (`File::sync_all`) and renames.
  - `load` returns what the two steps give.
  - `list` ignores every file whose name is not `<valid id>.toml`, including `*.tmp`. Two sessions with the same `opened` are ordered by id, ascending.
  - Named sessions are never pruned.
- **Check:** `cargo test -p navo-compare-profile --locked session > ../B4.log 2>&1; echo $?` prints 0. Tests cover a save and load round trip, ids `../x`, `a/b`, an empty id and a 41-character id, a relative side, a Git side without a rev, an unknown whitespace value, `Texts`, a newer file with fields this version does not know (load gives `Newer`, save leaves it byte for byte), a broken file that save leaves byte for byte, a file whose inner id differs from its name, a left-over `.tmp` file (the old session still loads), a missing folder, 25 unnamed and 3 named sessions pruned to 20 and 3, and the list order. Then clippy as in B1.
- **Stop if:** B3's `Profile` API differs from the B3 brief.

### B5 — bench data generator

- **Read:** NC17 and NC33 in the standalone plan; `Cargo.toml` (16 lines).
- **Change:** in `xtask`: `src/main.rs` (the command switch), new `src/bench_data.rs` and `src/bench_data_tests.rs`. The alias exists.
  - Command: `cargo xtask bench-data --set s|m|l --seed <u64> --out <dir> [--files <n>]`.
  - Sets S and M write `<out>/left` and `<out>/right`: S has 2,000 files, M has 200,000; `--files` overrides the count. 40 files per folder, at most 6 levels deep, each file 1–4,096 bytes of generated text. The count is the union of both sides.
  - Of the files: 2 % differ in content with the same size, 1 % differ in size, 0.5 % exist only left, 0.5 % only right. Each count is the share of the file count, rounded half up. The rest are the same bytes on both sides.
  - Set L writes `left.log` and `right.log` of 1 GiB each with 1,000 changed lines, and `left.bin` and `right.bin` of 1 GiB each with 16 changed bytes. It prints the 4 GiB size first. `--files` scales it for tests: each file has files × 1,024 bytes, the logs differ in `min(1000, lines / 8)` lines and the binaries in `min(16, bytes / 4096)` bytes.
  - The generator is a `xorshift64*` function in this crate; its state starts as `splitmix64(seed)`, so seed 0 works. The same set, seed and count give the same bytes on every host.
  - `--out` must be missing or empty; otherwise exit code 2 and nothing is written.
  - On success it prints one line: `files=<n> same=<n> changed=<n> resized=<n> only_left=<n> only_right=<n> bytes=<n>`. Set L prints `files=4`, zero for the four counts in the middle, and `bytes`.
  - `main.rs` may print; add `#[expect(clippy::print_stdout, reason = "command-line tool")]` only if clippy asks.
- **Check:** `cargo test -p xtask --locked bench_data > ../B5.log 2>&1; echo $?` prints 0. Tests run with `--files 400` in a temp folder: the counts match the percentages, two runs with one seed give the same manifest and the same bytes, two seeds differ, seed 0 gives non-zero bytes, a non-empty `--out` is refused, set L with `--files 64` differs in exactly the number of lines and bytes the rule above gives. No test writes more than 4 MiB. Then clippy as in B1.
- **Stop if:** a test would need more than 4 MiB or 60 s.
